# TestCase Generator 3 — 自主学习型测试用例生成器

从 PRD 文档（Word / Markdown / PDF / 图片 / URL）自动生成专业的 Excel 测试用例，支持**持久化记忆、质量门禁、需求追溯**，越用越准。

---

## 核心能力

| 能力 | 说明 |
|------|------|
| **多格式输入** | Word、Markdown、PDF、图片、在线文档 URL，通吃 |
| **Excel 输出** | 基于模板生成标准格式的 .xlsx 文件 |
| **8 种覆盖维度** | 功能/边界/异常/权限/网络/并发/场景/等价类 |
| **智能用例筛选** | "只要正向"、"不要异常"、"只要功能测试" 一句话搞定 |
| **持久化记忆** | 自动记录术语、偏好、历史，下次会话即刻生效 |
| **交互式检查点** | 快速模式，仅在关键节点暂停询问，不打断节奏 |
| **歧义决策复用** | 处理过的歧义自动记住，类似情况不再重复问 |
| **7 维度质量门禁** | 覆盖率≥95%、优先级分布校验、去重等，生成前拦截缺陷 |
| **需求追溯** | 双向追溯矩阵 + 覆盖率自动计算 |
| **历史趋势分析** | 每次生成自动对比，输出趋势摘要 |

## 快速开始

### 一句话生成

直接把 PRD 文档丢过来：

```
生成测试用例
根据这个文档生成测试
分析这个 PRD 生成测试用例
```

### 也可以带筛选条件

```
根据这个文档生成测试用例，只要正向
根据这个PRD生成测试，不要异常
根据文档生成测试，只要功能测试
```

### 支持多种输入

| 输入类型 | 示例 |
|---------|------|
| 直接粘贴文本 | 把需求文字发过来 |
| Word 文档 | 上传 `.docx` 文件 |
| Markdown | 上传 `.md` 文件 |
| PDF | 上传 `.pdf` 文件 |
| 网页链接 | 发送任意可访问的 URL |
| 设计图 | 上传 `.png` / `.jpg` 截图（建议配合文字描述） |

## 工作流程

生成过程全自动，你只需要在必要时点个头：

```
Phase 0 → 初始化记忆（首次运行自动创建 .memory/）
Phase 1 → 读取输入文档
Phase 2 → 解析需求 + 加载历史记忆 + 测试设计
Phase 2.5 → 检查点1：解析确认（有问题才问）
Phase 2.6 → 歧义处理（仅关键歧义，历史重复自动跳过）
Phase 2.8 → 检查点2：质量预审 + 覆盖率展示
Phase 3 → 生成 Excel 文件
Phase 4 → 更新记忆（生成历史 / 术语 / 偏好）
Phase 5 → 用户反馈学习（可选）
```

### 检查点说明

| 检查点 | 时机 | 需要你做什么 |
|--------|------|------------|
| **解析确认** | 解析完成后 | 查看识别到的模块和需求数，选择适用端（仅首次） |
| **歧义处理** | 检测到模糊描述 | 确认 AI 的理解是否正确 |
| **生成预览** | 生成前 | 查看用例数量和质量统计 |

## 记忆系统

首次运行后自动创建 `.memory/` 文件夹，所有学习数据自动保存：

```
.memory/
├── user-preferences.json      # 你的偏好（标签、步骤粒度等）
├── terminology.json           # 领域术语库
├── generation-history.json    # 生成历史（趋势分析用）
└── ambiguity-decisions.json   # 歧义处理决策
```

### 记忆管理命令

| 指令 | 效果 |
|------|------|
| `查看偏好` | 查看当前保存的用户偏好 |
| `更新术语表` | 手动维护领域术语 |
| `清除记忆` | 重置所有学习数据（慎用） |

## 质量门禁

每次生成前自动进行 7 维度检查，任一不通过则先修正再输出：

| 维度 | 标准 |
|------|------|
| 需求覆盖 | 每条需求至少关联 1 条用例，覆盖率 ≥ 95% |
| 方法覆盖 | 每条需求至少使用 1 种设计方法 |
| 优先级分布 | P0: 10-25%, P1: 30-60% |
| 步骤可执行 | 步骤明确、可操作，预期结果可验证 |
| 无需求外编造 | 所有用例来源于需求文档 |
| 术语一致 | 与需求文档和术语表一致 |
| 无冗余重复 | 无语义重复的用例 |

---

## 需求追溯

生成时自动建立需求 ↔ 用例的双向追溯：

- **正向追溯**：每条需求能查到覆盖它的所有用例
- **反向追溯**：每条用例 JSON 中记录 `req_id` 字段，标明来源需求
- **覆盖率计算**：`已覆盖需求数 / 总需求数 × 100%`，目标 ≥ 95%
- **遗漏检测**：自动标记未覆盖需求和孤儿用例

## 适用端（标签）

首次生成时会询问测试用例适用的端，选择会被记住：

| 编号 | 选项 |
|------|------|
| 1 | PC |
| 2 | APP |
| 3 | C端 |
| 4 | PC, APP |
| 5 | 小程序 |
| 6 | 其他（自定义） |

若需求文档中已写明（如 `tag只适用于PC端`），直接读取，不再询问。

## 反馈与学习

对生成结果提出修改意见，工具会自动学习：

| 你说的 | 工具做的 |
|--------|---------|
| "这条用例逻辑不对" | 重新生成 + 记录歧义模式 |
| "P2 太多了" | 询问是否调整默认优先级分布 |
| "还缺并发场景" | 增补用例 + 记录为常见遗漏 |
| "这里应该叫 XXX" | 询问是否写入术语表 |
| "步骤太细，合并一下" | 询问是否记住粒度偏好 |

## 常见问题

**Q: 支持哪些输入格式？**  
A: Word (.docx)、Markdown (.md)、纯文本 (.txt)、PDF (.pdf)、图片 (.png/.jpg/.jpeg/.gif/.webp)、任意可访问的 URL。

**Q: 生成的文件在哪里？**  
A: 在项目根目录，文件名格式 `testcases_<14位时间戳>.xlsx`，不会覆盖历史结果。

**Q: 支持多次生成同一份需求吗？**  
A: 支持。直接再次触发，会以新时间戳生成新文件。

**Q: 怎么让工具记住我的偏好？**  
A: 生成后直接说（如"步骤细一点"），工具会询问是否持久化。
